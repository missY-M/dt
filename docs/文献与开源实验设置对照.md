# 老师文献与相关开源项目：实验设置、基线和可借鉴部分

核对日期：2026-10-26。依据四份本地论文的正文、实验表图，以及下列项目的README和实验源码。已对关键PDF表图进行视觉核对。本次没有安装或运行这些外部项目，没有修改当前实验代码和参数；下面的建议不是已完成的实验结果。

## 1. 先回答能不能参考

可以参考，但要分开三件事：实验组织方式、可适配的算法规则、具体参数数值。老师文献研究的分配粒度不同，不能把所有基线和数字直接搬到当前课题。

当前课题的第一阶段是：复杂请求已拆成子任务，每个子任务完整分给一个节点，依据需求和能力进行匹配与联合分配。当前没有训练模型、DNN切层、车辆移动或云端兜底。

| 来源 | 主要研究对象 | 与当前课题的关系 |
|---|---|---|
| 老师第1篇CAO | 同一DNN的分组、分布式训练和流水推理 | 能力表达和异构/失效压力设计可参考；训练与切层基线不能直接搬 |
| 老师第2篇HCIO | 推理任务卸载、DT放置、资源分配和AoI | 多节点卸载和实验扫描方式较接近；车辆/DT部署条件不同 |
| 老师第3篇Adaptive Device-Edge | 一个设备和一个边缘之间的DNN停止/卸载决策 | 参数化仿真、长期排队影响和DT消融可参考；动作空间不同 |
| KDN架构论文 | 网络意图、策略匹配和网络管理 | 框架分工和动态异常场景可参考，不是任务调度算法的直接基线 |
| SAGA | 异构计算网络上的任务图调度 | 可借经典调度器及任务图基准设计，需适配质量/内存/在线条件 |
| OpenDAG-Agent | 语言代理工作流的任务图放置仿真 | 可参考通用任务图、能力约束和通信/计算权衡；含云/API，当前课题不能照搬 |
| DT_elastic-workbench | 服务的资源/输入质量/模型配置调整 | 可参考测量字段和DT辅助决策，不是多个节点之间的整任务分配 |

这几篇并不都依赖真实模型测量：HCIO是移动轨迹驱动的参数化仿真，老师第3篇也明确是仿真。使用一个具体DNN结构作为实例，与调度方法是否通用，是两个层次的问题。

## 2. 老师第1篇CAO

原文件：`D:/onedrive/Desktop/文献/1. Capability-Aware Distributed Learning and Inference for Heterogeneous 6G Edge Environments (1).pdf`。重点证据：PDF第3页公式、第4页IV-A/IV-B、第5页表I–III和IV-C、第6页图3。

### 2.1 实验设置

| 项目 | 论文设置 |
|---|---|
| 图像数据 | CIFAR-10，50,000训练图像、10,000测试图像、10类 |
| 模型 | ResNet-18，分10个可执行组g0～g9 |
| 数据分配 | IID均匀分配；Non-IID采用对称Dirichlet，α=2.0 |
| 节点 | 8个异构边缘节点；算力、内存和带宽不同 |
| 分组部署 | 输入g0和输出g9作为共享spine，其他组由编排器分配 |
| 能力评分权重 | 计算0.3、FLOPS0.3、带宽0.2、可用性0.1、能量0.1 |
| 组成本系数 | FLOPs为10^-6、参数数为10^-3、激活内存为10^-3 |
| 分配窗口 | ceil(可分配组数/节点数)+2，相邻2组重叠 |

论文未清楚交代具体CPU/GPU型号、内存/带宽数值、仿真平台或物理平台，因此不能推断成“8台真实边缘设备”。用了真实图像数据集，并不自动补齐其硬件复现信息。

### 2.2 基线分训练和推理两组

训练比较：

| 基线 | 含义 |
|---|---|
| FL | 每节点训练完整模型，服务器聚合 |
| SL | 模型按层切分，跨节点顺序执行 |

推理比较：

| 方案 | 含义 |
|---|---|
| Single-Node (Weak) | 弱单节点执行同一模型 |
| Single-Node (Medium) | 中等节点执行同一模型 |
| Single-Node (Strong) | 强单节点执行同一模型 |
| Random Pipeline (3-Node) | 3节点随机流水分配 |
| CAO Pipeline (3-Node) | 作者的3节点能力感知流水方案 |

推理图中各方法质量均为93.40%。作者也指出最强单节点最快，因为无需跨节点通信。不能把它描述成作者方案战胜所有参照。

### 2.3 压力场景、指标与缺口

压力场景包括资源异构但一直可用、epoch50后永久移除最强2节点、每通信轮随机25%节点不可用。所有方法使用early stopping，但未说明阈值和耐心值。

训练报告准确率、训练时间、累计训练参数量和通信量；推理报告时间和准确率。不同表的通信单位有MB/GB差异。Params(B)表示累计训练参数量，不能当成单个模型参数规模。推理133.3秒等计时未明确输入数量和batch口径，不能当作每张图时延。

没有明确给出优化器、学习率、batch size、最大epoch、随机种子/重复次数或误差条。本地文件没有作者代码链接，也没有明确发表载体，不能用PDF生成日期代替发表日期。正文epoch50失效与表II脚注epoch47–49还存在时间描述差别。

### 2.4 对我们有用的部分

可以借鉴双画像、节点异构/失效压力、保留强参照的实验原则。不应把FL/SL直接当作当前整子任务选节点的同问题基线，也不需要为照搬该文去训练ResNet-18。

## 3. 老师第2篇HCIO

原文件：`D:/onedrive/Desktop/文献/2. Age-of-Information-Aware_Hierarchical_Collaborative_Inference_in_Digital_Twin-Enabled_Vehicular_Edge_Computing.pdf`。重点证据：PDF第11–14页，尤其第12页表III和图4、第14页图8/9。[期刊入口](https://doi.org/10.1109/TNSE.2025.3615533)。

### 3.1 实验性质与数据

使用Telecom Shanghai Dataset中的移动轨迹，在参数化任务、资源和网络模型中仿真。论文参考文献给出的[数据地址](https://www.kaggle.com/datasets/mexwell/telecom-shanghai-dataset)在这里作为作者提供的入口，不表示已下载并验证数据。

真实的是移动轨迹；推理输入大小、计算量和模型深度等仍按参数表示，没有真实视觉模型准确率测量流程。仿真宿主机为AMD Ryzen 9 9950X、96GB RAM、RTX5090，不能把该宿主机当成每个虚拟节点的硬件。

### 3.2 参数

| 项目 | 原文设置 |
|---|---|
| 区域 | 5km×5km |
| 基站及共址边缘服务器 | 9个 |
| 通信半径 | 1.5km |
| 车辆数 | 表/正文400～1000；图4(a)横轴另从300起 |
| 每车辆任务生成 | 每时隙以概率ρ生成任务，ρ=0.05～0.85 |
| 边缘计算容量 | 基准100GHz，扫描40～180GHz |
| 边缘存储 | 基准50GB |
| 空闲协作终端 | 1～3GHz |
| 上行带宽 | 10MHz |
| 车辆发射功率/噪声 | 0.5W / −100dBm |
| 边缘间有线速率 | 1Gbps |
| 输入大小 | 2～5Mb，均匀分布 |
| 输出/输入比例 | 0.1 |
| 计算强度 | 100～400 cycles/bit |
| 时限 | 300～1000ms |
| 模型深度 | 5～10 |

单位不可直接搬：Mb是兆比特，2～5Mb约为0.25～0.625MB；GHz表示cycles/s，不等于当前项目GFLOP/s。ρ是每车辆每时隙概率，不是全系统请求/秒，转换还需要车辆数和时隙长度。

### 3.3 六个基线的准确做法

| 基线 | 原文做法 |
|---|---|
| RILP | 放松任务卸载/DT放置二元变量到[0,1]，求线性规划，在资源可行条件下舍入 |
| GPDO | DT部署到最近边缘，任务贪心卸载到最近可行节点 |
| PDO | 优先处理时限更紧的车辆，再卸载到剩余资源足够的最近服务器 |
| DDRO | 时延优先放置，从满足资源/时限的候选中随机选卸载节点 |
| DRL-TDO | DDPG，actor用Gumbel–Softmax参数化，critic估计长期期望回报 |
| Fed-TDO | 边缘基于本地负载训练策略，协调器用联邦平均聚合和分发 |

HCIO自身不是DDPG，不能把DRL基线与作者算法混淆。以上方法联合考虑任务卸载和DT放置，改到当前固定DT画像场景后只能叫适配规则，不能声称原样复现。

### 3.4 实验组织与复现边界

扫描用户数、服务器计算容量、任务生成概率和模型计算复杂度；还检查静态/正弦/随机容量、带宽×CPU热力图、移动预测噪声及安全裕量、算法可扩展性与9服务器利用率。

指标包括AoI、卸载任务数、卸载数据量、截止违反率、计算/存储利用率和算法时间。图8(c)明确95%置信区间，但未明确种子、重复次数、完整运行时长或时隙秒数。图中展示100时隙不表示全篇所有实验都只运行100时隙。没有明确软件仿真器或作者代码链接。

可借鉴的是多维扫描、强基线类别、服务量与时限/利用率/开销同时报告。当前无需为此引入车辆移动、无线信道或DT放置；AoI也不能直接替代模型能力质量漂移。

## 4. 老师第3篇Adaptive Device-Edge

原文件：`D:/onedrive/Desktop/文献/3. Adaptive_Device-Edge_Collaboration_on_DNN_Inference_in_AIoT_A_Digital-Twin-Assisted_Approach.pdf`。重点证据：PDF第11页表I、第11～13页VIII和图6～13。[作者公开PDF](https://uwaterloo.ca/scholar/sites/ca.scholar/files/sshen/files/hu2024adaptive.pdf)。

### 4.1 实验设置

一个重点研究的AIoT设备和一个边缘服务器；其他设备通过背景任务体现。设备运行浅层DNN，边缘运行完整DNN；决定每层前继续本地还是卸载，允许浅层退出。这不是多个候选边缘节点的整任务选择。

明确采用仿真。完整模型结构为AlexNet，逐层时间按FLOPs和计算频率估计；完整/浅层质量固定0.9/0.6。没有列出真实图像测试集和准确率测量过程，不能说这些质量是该实验实测。

| 参数 | 原文设置 |
|---|---|
| 时隙 | 10ms |
| 设备/边缘计算频率 | 1GHz / 50GHz |
| 浅层退出位置 | 2 |
| 完整/浅层质量 | 0.9 / 0.6 |
| 上行速率 | 126Mbps |
| 发射功率 | 20dBm |
| 能效系数 | 10^-30 |
| 准确率权重 | 1.0 |
| 能耗权重 | 表I为0.2；图9解释正文另写0.002，不能统一混写 |
| ContValueNet | 三层全连接200/100/20，Adam，学习率10^-3 |
| 学习/评估 | 前2000个任务训练决策价值网络，后8000个任务评估 |

2000任务不是2000张图训练AlexNet，8000任务也不是8000次独立仿真。未明确随机种子、重复次数或置信区间。

### 4.2 负载和三个基线

设备任务按每时隙Bernoulli概率p生成，速率p/ΔT。边缘背景任务按Poisson到达，计算需求均匀U(0,8×10^9) CPU cycles。边缘无量纲负载为ρ=λUmax/(2fE)。实验扫描设备生成率0.2～1.0请求/秒，背景负载0.6～0.9。

| 基线 | 做法 |
|---|---|
| One-Time Ideal Case | 任务生成时决策一次，完美知道未来负载，优化长期效用；理想信息参照，不是可在线实现方法 |
| One-Time Long-term | 任务生成时决策一次，根据当前状态优化含后续排队影响的长期效用 |
| One-Time Greedy | 任务生成时决策一次，根据当前状态优化当前任务效用 |

作者方法为最优停止、ContValueNet、DT反事实训练增强和决策空间裁剪，不是DDPG/PPO。其One-Time Greedy与当前代码qos_greedy的目标、动作和约束不同。

### 4.3 指标、消融和可借鉴部分

报告效用、平均时延、质量参数、能耗；效用为−时延＋α×质量−β×能耗。另做有/无DT训练增强、有/无决策空间裁剪。复杂度图统计每任务继续/停止判断次数，不是总程序秒数。

最值得借鉴的是容量归一化负载、学习和评估分离、DT模块及搜索加速分别消融、当前信息与理想信息分开评价。当前方法没有学习过程，不必机械设置2000训练任务；将来若学习质量/状态预测器，再分训练和评估数据。

原文表I与图9说明中的能耗权重不同，复现应明确选择或向作者确认，不能默默修成一个数。本轮未核实到作者开源实验实现。

### 6.1 SAGA：借经典基线和任务图实验

[仓库](https://github.com/ANRGUSC/saga)，核对提交`5b20e8d31aec029b0a4d785b8d55d49d9444ea13`。

关键源码：[数据生成](https://github.com/ANRGUSC/saga/blob/5b20e8d31aec029b0a4d785b8d55d49d9444ea13/scripts/experiments/benchmarking/prepare.py)、[当前benchmark基线](https://github.com/ANRGUSC/saga/blob/5b20e8d31aec029b0a4d785b8d55d49d9444ea13/scripts/experiments/benchmarking/common.py)。

- 随机入树、出树、并行链，每类默认100个实例，随机计算网络3～5节点；树层数2～4、分支2～3，链数/长度2～5。
- 提供RiotBench与WfCommons生成入口，但当前默认排除清单会跳过列出的WfCommons配方，不能说运行默认脚本就一定包含这些集。

- 适合参考任务图、计算与通信代价、经典调度器及同实例比较方式；不是模型准确率基准，没有当前质量画像硬约束。
- 当前版本需Python3.12+，不能默认直接装入现有Python3.10环境。若后续需要运行，应独立环境或适配规则，保持EdgeSimPy现有环境稳定。

对当前两个并行子任务，Min-Min等独立任务规则容易比较；HEFT更适合后续显式依赖任务图。若修改候选筛选或执行顺序，应说明是适配版本，不能拿原方法名字掩盖差异。

### 6.2 OpenDAG-Agent：借通用任务工作流的仿真方式

[仓库](https://github.com/ANRGUSC/opendag-agent)，核对提交`13df53e46a68c3f9c31de497e745ed5e123b324f`。

关键源码：[完整实验](https://github.com/ANRGUSC/opendag-agent/blob/13df53e46a68c3f9c31de497e745ed5e123b324f/experiments/e1_campaign.py)、[资源参数](https://github.com/ANRGUSC/opendag-agent/blob/13df53e46a68c3f9c31de497e745ed5e123b324f/opendag/presets.py)、[基线约束](https://github.com/ANRGUSC/opendag-agent/blob/13df53e46a68c3f9c31de497e745ed5e123b324f/opendag/schedule/baselines.py)。

- 工作流5类：map-reduce、层次研究、辩论、流水线验证、边缘感知融合；README概括任务规模10～100。
- 完整实验调用6个边缘站点，另有mid节点和API虚拟执行通道。三个网络制度下总执行者分别9/10/13，不是总共只有6节点。
- 边缘上行带宽为60/250/1250kB/s三档；默认边缘、中间、两API档速度8/20/70/50 tokens/s，均为声明参数，不是该版本实际profiling结果。
- 能力用SMALL/MEDIUM/FRONTIER等等级及固定放置约束表示；模拟客户端不真实调用语言模型API。
- 完整脚本比较19个经典调度器、6个简单参照和代价权重扫描。6个参照为AllAPI(sonnet)、AllAPI(haiku)、LocalFirst、RoundRobin、Random(42)、GreedyCheapest。
- 目标是工作流总完成时间和美元成本等，不是当前每请求质量门槛与截止同时满足的QoS。

可以借鉴“不同任务共用统一画像接口”“能力约束所有方法一致”“扫描通信/计算环境和工作流规模”。当前无云/API和费用目标，不能照搬AllAPI或其美元成本；能力等级也不能直接等同于实测准确率。该项目是研究代码参考，不在这里把它当作已确认的同行评审论文基线。

### 6.3 DT_elastic-workbench：借测量字段和服务控制

[仓库](https://github.com/ElenaPretelFdez/DT_elastic-workbench)，核对提交`759f9e5fb448ee08976f881befa97e692f803396`。

关键源码：[AIF入口](https://github.com/ElenaPretelFdez/DT_elastic-workbench/blob/759f9e5fb448ee08976f881befa97e692f803396/IoT2025/predictability_DT_AIF_agent.py)、[SLO](https://github.com/ElenaPretelFdez/DT_elastic-workbench/blob/759f9e5fb448ee08976f881befa97e692f803396/config/slo_config.json)、[控制范围](https://github.com/ElenaPretelFdez/DT_elastic-workbench/blob/759f9e5fb448ee08976f881befa97e692f803396/config/es_registry.json)。

项目包含QR检测与视觉分析服务容器，AIF配置默认资源预算8核。动作包括保持、调输入质量、调CPU核数、视觉服务调模型大小；每服务核数候选1～7且合计受预算约束。视觉输入配置128～320、模型档位1～5；QR配置300～1000等离散档，SLO配置给出吞吐与输入质量目标。

这里data_quality主要是服务输入质量/分辨率配置，不是直接测得的模型回答准确率。代码包含概率模型支持的训练环境；默认AIF入口的50步训练不等于完整实机评测流程。README要求Python3.12和Docker。

适合后续学习记录吞吐、分辨率、CPU和模型配置之间的关系，以及DT辅助动作评价。当前控制对象是服务配置，不是我们的多节点放置；未在本次核对中确认一套可直接移植的完整性能基线列表。

## 7. 这些文献和代码体现的可借鉴实验习惯

1. 通用调度方法可以用具体模型结构举例，也可以使用抽象计算/通信参数；真实业务轨迹与真实模型评测数据是不同来源。
2. 不只跑一个默认点，会变化任务规模、资源、负载、计算/通信比例、动态条件。
3. 基线要覆盖简单规则、较强启发式、合适的优化参照；有学习模块时再选学习基线，不因“数字孪生”三个字就必须上强化学习。
4. 用消融分别证明推荐、联合选择、DT更新等模块的额外作用，避免全方法对弱基线却说不清哪部分有效。
5. 指标要和研究目标一致，并同时报告服务质量、拒绝/失败、时延和决策开销。
6. 论文没有写的种子、重复或参数不能替作者补。我们应把自己的种子、来源和误差统计写得更明确。

## 8. 我们当前阶段可以怎样参考

以下是针对现有项目的建议，不是老师已指定的数字，也不是上述论文的复现。

### 8.1 保留现有平台和最小场景

继续使用EdgeSimPy，保留6节点、2类任务作为起步点。无需因为其他项目采用不同工具或真实模型就更换当前平台。当前静态画像阶段不必立即加车辆移动、云端API或DNN切层。

### 8.2 更有解释力的对比组合

| 类型 | 建议 | 需说明的适配 |
|---|---|---|
| 简单参照 | 轮询、随机可行节点、最早完成 | 统一类型/内存条件；质量/预计时限是否硬筛选分别交代 |
| 直接强参照 | 现有QoS贪心 | 保持和联合方案相同画像、预测、约束及排序 |
| 经典调度 | 从Min-Min入手，依赖图阶段再考虑HEFT | 加入候选限制后应命名/说明适配，不宣称原样文献复现 |
| 小规模精确参照 | 当前批次按相同预测模型枚举或求解 | 仅评价近似搜索损失，不是整个在线实际QoS的绝对上界 |
| 候选方案 | 当前联合分配及后续改进 | 不能提前预设一定胜出 |

HCIO的最近节点、时限优先和随机可行规则可以启发基线，但当前无车辆位置、无DT放置，不能直接叫GPDO/PDO/DDRO完整复现。CAO的FL/SL与OpenDAG的AllAPI不适合作为当前同问题直接基线。

### 8.3 先做能解释模块作用的消融

- 有/无推荐评分：保留相同质量/资源/预计时限检查，只去掉评分奖励S，避免把“没有质量检查”误当作“没有DT”。
- 有/无联合选择：保留画像、预测和约束，尽量统一目标与排序。当前贪心与beam的代价汇总粒度也有区别，不能把所有差异都归因于搜索宽度。
- 后续再增加精确信息/延迟信息、质量固定/变化、有无重调度。这些是后续研究点，不应提前当作已实现。

### 8.4 参数扫描的建议顺序

| 顺序 | 变化项 | 为什么 |
|---|---|---|
| 1 | 请求负载，从轻到接近拥塞 | 找方法在排队和网络竞争下的差别 |
| 2 | 截止时间紧迫程度、质量门槛 | 检查真正的QoS取舍 |
| 3 | 节点能力异构、同类任务可选节点数量 | 检查画像匹配及稀缺能力的作用 |
| 4 | 每请求子任务数、节点数，例如6/9/12节点 | 检查复杂度与可扩展性，数字是建议而非引用值 |
| 5 | 同步/突发到达 | 当前默认批次通常只有1请求，需另外检查跨请求联合性 |
| 6 | 带宽、计算量及二者比例 | 区分通信瓶颈与计算瓶颈 |
| 7 | 权重、beam宽度、时间步 | 证明结论不只依赖一个超参数 |

任务类型数与每请求子任务数应尽量分开控制，当前生成器按每类型一个任务，两者耦合；扩大实验前需要明确新模板。正式统计可考虑每轨迹500或1000请求、5～10种子，但具体数量应根据运行成本和波动决定，不能说这是领域统一标准。

负载不要只照抄论文请求/秒。可以先看“到达的平均计算需求/资源容量”和“到达数据量/带宽”的归一化压力，再用试跑确认拥塞范围。老师第3篇的ρ正体现这种设计。

以当前均值粗算：每请求输入2.5+4MB、输出0.02+0.10MB，共6.62MB经过骨干；2请求/秒对应13.24MB/s，相对30MB/s约44.1%。这是忽略拒绝的平均提供数据负载估算，不是实际CPU利用率，也不排除突发或接入瓶颈；它说明2请求/秒不能仅凭数字就称为饱和压力。

### 8.5 数据与结果怎样写

短期可以继续纯仿真，给每项参数标明“论文借鉴/公开轨迹/合成设定”。若借HCIO参数，应统一bit/byte及cycles/FLOP模型，不能换个单位标签直接用。真实模型测量可以在需要校准画像时增加，不是当前必须立刻完成的前置条件。

指标建议保留请求QoS、拒绝、未完成/超时、画像质量失败、平均/P95时延、CPU/网络利用率、调度开销与预测误差。QoS仍是画像门槛与实际仿真时限，不等于实际模型答案正确率。

当前联合搜索尚未稳定超过QoS贪心。后续应先提出“在哪些资源互补、稀缺候选或突发条件下，联合性应有帮助”的可检验假设，再设计场景验证，而不是调参数制造领先。
